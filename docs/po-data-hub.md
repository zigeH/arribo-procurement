# PO data hub (feature 1)

Goal: one place where a buyer sees what is really happening with each PO,
combining the ERP with what suppliers say in email (later: files, WeChat Work),
and a daily list of where they disagree.

## Pipeline

```
ERP (read-only)  ──►  normalized POs + goods receipts ─┐
supplier email   ──►  extract events ──► match to PO line ─┼─► per-PO timeline (with sources)
                                          │                └─► 对不上清单 (discrepancies)
                                          └─► review queue (uncertain)      └─► enriched data → scoring
```

- **ERP**: `connectors/erp.Reader`. First adapter: SAP Business One Service Layer
  (`/Login`, `/PurchaseOrders`, `/PurchaseDeliveryNotes`, `/BusinessPartners`,
  OData paging), read-only user. MLOptic = SAP B1 is an inference from a public
  implementer case page; confirm with MLOptic. The interface is ERP-agnostic.
- **Extraction**: `extract.Rules` (deterministic zh/en baseline) and `extract.LLM`
  (Anthropic Messages API, JSON output). The LLM is the production path for real
  phrasing; the rules baseline exists for tests, evals and offline demos.
- **Matching**: sender domain → supplier (then supplier name in signature);
  PO number (prefixed, or a bare 6-digit number in the subject); line by line
  number, part number, or the only line. Unknown sender, PO of another supplier,
  ambiguous line, or low confidence → **review queue**. A wrong entry on a timeline
  is worse than a missing one.
- **Discrepancies** (as of any date): `date_mismatch` (supplier date ≠ ERP),
  `price_mismatch` (supplier price ≠ ERP: invoice won't match), `shipped_not_received`,
  `overdue_no_update`, `unacknowledged`, `quality_issue`.
- **Scoring consumes the hub**: first confirmed date and acknowledgments come from
  supplier messages (`Hub.EnrichedDataset`).

## Eval numbers (rules baseline, synthetic data)

| Set | Result |
|---|---|
| Templated corpus (89 emails) | extraction P/R 1.00 all types, fields 1.00, matching 1.00, discrepancy recall 1.00, 0 false alarms |
| Hand-written hard set (14 emails) | recall 0.60, **0 confidently wrong**, 4 to review |

The templated corpus is generated by the same templates the rules were written
against: it proves plumbing, not accuracy. The hard set was used to fix the rules
(no longer truly held out). Real accuracy needs real (sanitized) emails and the
LLM extractor.

## What we need from MLOptic

1. ERP product and version (SAP Business One? which version / HANA or SQL?), and
   whether the US entity uses the same system.
2. A read-only Service Layer user, and how we reach it (VPN / IP allowlist /
   on-prem agent), or scheduled exports as a fallback.
3. Mail system (腾讯企业邮 / Microsoft 365 / other) and which mailbox(es) carry
   supplier mail; whether forwarding/CC to an Arribo address is acceptable.
4. A sample of sanitized supplier emails (incl. Chinese, forwarded threads,
   attachments) to measure real accuracy.
5. Written approval for sending email content to an LLM provider (no training).
